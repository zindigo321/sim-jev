## 实施顺序

1. 检查目录、Git、适用指令及指定 Python。保护现有研究记录；不重建环境。
2. 用 dataclass 定义显式状态，heapq 建立唯一事件引擎；配置和规则独立。
3. 实现固定时刻任务、稳定派机、飞行小时寿命和任务整体中止。
4. 加入维修机位、备件扣减、订单及每日库存位置补货。
5. 实现事件间隔积分、合法观测、审计状态导出、CLI 和结果图。
6. 按验收清单运行确定性单测、default、stress、两场景 seed 0—9；检查输出。
7. 独立审查、修复及回归，补齐中文说明和实测验证记录；不提交或推送。

## 模块与接口

- `config.py`：JSON 参数、类型及数值域校验。
- `models.py`：飞机、任务、维修、订单、事件的显式数据结构。
- `policy.py`：按 ID 派机、故障先到先修、库存位置订购。
- `engine.py`：时间推进、事件处理、不变量、`reset/run/get_observation/export_state`。
- `metrics.py`：累计积分与指标口径；`reporting.py`：表格、JSON 和图形。
- `__main__.py`：CLI。测试调用真实引擎；无数据库、Web、SimPy 双实现。

## 预先固定的假设

同刻顺序：故障 → 维修完成 → 到货 → 任务结束 → 尝试维修 → 补货检查 → 任务开始。
同类事件按确定性入队序号；同时任务按 ID 入队。事件生成的同刻事件重新进入该顺序。
截止时刻事件处理，截止之后保留队列和实体状态。可用包含空闲与正在飞行。
库存位置 = 在库 + 在途 − 所有等待维修需求；在维修开始时才消耗备件。
任务开始时才公布任务；观测不暴露实际剩余寿命、随机状态或未公布未来任务。
